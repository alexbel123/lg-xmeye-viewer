# Макет «Камеры» v0.4

Интерактивный макет для согласования интерфейса телевизионного приложения.
Рабочее приложение 0.3.1, видеосервис, сохранённые учётные записи и телевизоры не изменялись.
Макет не обращается к регистраторам. Все кадры демонстрационные, сгенерированные.

Открыть `index.html` или запустить из корня проекта:

```powershell
python -m http.server 19448 --bind 127.0.0.1 --directory design/prototype-v0.4
```

Адрес: http://127.0.0.1:19448

## Сценарии

- Сетки 1, 2, 4 и 6 окон. Если в наборе больше камер, чем окон, они распределяются по страницам. Смена сетки не удаляет камеры.
- Один клик по камере или OK открывает её на весь экран. «Назад», повторный клик или «К сетке» возвращает прежний набор, страницу и выделение.
- Именованные наборы сохраняют название, порядок камер и сетку. В примерах «Периметр» — 1,3,5,7; «Рабочие зоны» — 3,5,8,9; «Весь объект» — 1,3,5,7,8,9.
- Редактор позволяет выбрать камеры, переименовать набор и поменять порядок стрелками справа.
- «Скрыть панели» оставляет только камеры и одну кнопку «Меню» в левом верхнем углу. Через неё доступны наборы, сетка и настройки. Выбор набора сохраняет чистый режим.
- Левое меню и крупные кнопки предназначены для Magic Remote и навигации стрелками. «Назад» последовательно закрывает редактор, меню, увеличенную камеру, затем чистый режим.
- Настройки подписей и последнего набора сохраняются локально в прототипе.

Данные макета используют только отдельные ключи localStorage `viewer.design.v4` и `viewer.design.preferences`. Пароли и настройки рабочего приложения не читаются.

## Источники решений

[Synology: Layout Management](https://kb.synology.com/en-sg/SurveillanceStation/help/SurveillanceStation/monitor_center_layout_management?version=9) — именованные виды и отдельное управление раскладкой.

[Milestone XProtect: Viewing live video](https://doc.milestonesys.com/xprotect/xprotect-web-client/2026r1/en/viewing-live-video) — раскрытие одной камеры из вида одним кликом и возврат в тот же вид.

Внешний вид нарисован для этого приложения. Логотипы, код и скриншоты этих продуктов не использовались.

## Проверка

`verify.cjs` запускается через Playwright CLI в отдельной сессии, открытой на порту 19448:

```powershell
npx.cmd --yes --package @playwright/cli playwright-cli -s=lg-design open http://127.0.0.1:19448 --browser=chrome
npx.cmd --yes --package @playwright/cli playwright-cli -s=lg-design --raw run-code --filename=design/prototype-v0.4/verify.cjs
```

Проверены размеры 1280×720, 1366×768, 1920×1080; сетки и страницы; создание, переименование, сохранение и порядок камер; переход на весь экран и обратно; меню в чистом режиме. Результаты и скриншоты: `output/playwright/design-v0.4/`.

## Граница макета

Здесь шесть окон показаны на демонстрационных изображениях. Рабочий видеосервис по-прежнему имеет проверенный лимит четыре реальных потока. Изменение этого лимита и проверка нагрузки не входят в визуальный макет и не выполнялись на телевизоре.

При переносе в приложение увеличиваться должен уже работающий canvas камеры: без нового входа, переподключения или пересоздания остальных потоков. Сохранённый набор следует связывать с ID регистратора и индексом канала, а не только с отображаемым номером. Реальное видео должно сохранять соотношение сторон; фотографии здесь используются как иллюстрации.
